# 服务监控（Windows 第一版）

“工作空间 → 服务监控”由可独立启停、卸载的官方扩展 `toolhub.builtin.services` 提供。它仅观察 ToolHub 后台启动的程序、Agent 明确登记的进程和用户明确选择的代理端口，不建立全机进程或软件目录。新版本升级只添加一次此扩展；卸载后不会重启时重新安装，扩展目录可以手动恢复安装。

## 使用

- 从程序架后台启动，或在服务页选择已收录入口“启动并监控”。程序收录仍须用户先选择并保存；Agent 登记不自动收录程序或启动它。
- 服务卡片显示项目名称、实际应用图标、进程名、项目目录、PID、运行时长、可获取的工作集内存和 TCP/UDP 监听端口。无原生图标时采用现有工具图标兜底；无指标时不伪造数值。命令入口以真实子进程应用（如 Python/Node）显示图标，保持自定义项目名为主标题。
- 点击端口复制地址。HTTP 前缀只是网页入口建议，不探测协议、发送请求或证明服务健康；UDP 绑定也不是 TCP 监听。
- “停止”发送正常窗口关闭请求；无窗口 CLI 可能无法响应。此时可明确确认“强制结束”。受管服务结束整个进程组；Agent 登记的外部服务只结束核验的单个进程，不猜测外部进程树。
- 关联已有程序后支持重启；运行中重启会明确确认结束，再确认旧进程组退出，才启动新实例。状态不明时拒绝重叠启动。旧实例保留历史。
- 默认 120 分钟提醒，仅在当前服务页显示，不是系统通知。可单独修改或关闭。
- 明确设置从现在起的运行时限（1–10080 分钟）并确认后，到期允许强制结束受管服务及子进程。不是闲置检测；没有网络请求、关闭网页、低 CPU 都不触发停止。Agent 登记的外部服务不能设置自动停止。
- 主后台 daemon 重启、扩展停用/卸载或更改代理观察端口时，已有运行时限暂停，需用户重新配置，不自动补执行。关闭桌面窗口而 daemon 继续运行时，已明确配置的运行时限仍生效。移除监控只移除记录，不停止或删除程序；移除前须取消已有自动停止。

## 代理

代理是持续应用，只读显示。用户可指定最多 8 个名称/端口（例如 Clash:7897、nano:65532），只读取这些端口的监听状态和实际进程图标。代理类型登记、已知代理名称、观察端口或系统代理端口匹配的服务不会提供停止、重启或自动停止；后端也独立拒绝。

系统代理读取当前用户 WinINet `ProxyEnable` / `ProxyServer` 与 `AutoConfigURL` 是否配置。不会写注册表、改变开机启动、切换代理、获取 PAC、发送测试请求或修改代理软件配置；PAC URL 可能含令牌，因此只显示是否存在。服务器地址移除 URL 用户信息。TUN/VPN、WinHTTP、浏览器专属代理和其他进程启动时继承的代理环境变量均不能由这些信息判定，显示为未检测。端口监听不证明可以访问互联网。

## Agent 接入

```
register_service({"name":"项目预览","pid":12345,"project_dir":"D:/projects/example","kind":"web"})
list_services({"limit":10,"offset":0})
```

`kind` 是 web/model/proxy/other。只能登记实际存在、当前用户的非关键、非系统目录进程；ToolHub 自身和系统桌面进程被拒绝。Agent 不可提交启动命令、控制权、自动停止或代理配置。`list_services` 只返回当前认证调用方登记的记录（默认10，最多50），桌面可以查看全部，最多200条历史、每来源64条。MCP 共19个固定元工具，不按服务或端口增加工具定义。普通 Agent 与第三方隔离页面均不能调用控制接口。

原有 Skill 接入只在确实启动长期项目服务后提示登记，不要求反复列举全部服务或等待桌面处理。登记失败不改变宿主权限。

THP：service.register/list 为普通观察；service.start/stop/restart/configure/remove/proxy_status/proxy_configure 需要 OS 验证桌面身份。参数最大8KiB。观察元数据不是执行授权。通过现有用户程序启动入口执行的命令仍是用户明确收录的命令，不改变受控工具执行的信任、策略或审批。

## 实现与限制

Windows 原生 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在进程创建时原子关联进程组；默认子进程继承，停止操作针对持有的 job handle。没有按进程名/端口批量 taskkill，也不杀可能复用的 PID。外部进程以 PID、原生创建时间和真实映像路径绑定；停止前打开并持有同一进程句柄。进程组成员用于图标/正常关闭时会再核验成员身份。

命名进程组通过无窗口的轻量生命周期守护保持至该组退出，避免 daemon 更新重启后丢失身份；最多32个并行受管服务，不设置 kill-on-close，不因桌面/守护退出结束服务。它不是 OS 沙箱，WMI、外部服务管理器或已有单实例软件接管启动的进程不保证属于该组；快捷方式仍按原方式启动，暂不纳入受管服务。未知或权限不足显示状态待核验，不降级为任意 PID 结束。

每个记录最多30条历史；界面每页6项、历史显示最近6条，无内嵌滚动列表。TCP/UDP IPv4/IPv6 内核表有8MiB上限，只返回已选PID/代理端口；每条最多观察256个进程与256个端点，达到边界显示受限。界面可见时按所选间隔刷新（5秒/30秒/1分钟/2分钟/手动，默认30秒，按桌面配置记忆）；切回可见时自动模式立即刷新一次；手动模式仅打开页面、点击刷新或执行操作时更新，后台运行时限每10秒检查，所以执行有最多约10秒调度延迟。停止可能丢失未保存数据或留下不完整输出，不清理任何文件。

macOS/Linux 返回明确不可用，不通过 shell 降级。Windows 本机验证不代表其他平台已验证。

## 打开服务页面

在服务管理中保存明确的 HTTP/HTTPS 页面地址，卡片显示地址并提供“打开页面”。只在用户点击时交给 Windows 默认浏览器，不指定浏览器、不发送探测请求、不更改服务或系统代理。地址可与托盘监听端口不同，例如独立子服务或 mDNS HTTPS。没有地址时按钮禁用，不凭端口猜测 TLS 或访问路径。地址只能由经过验证的桌面修改；Agent 登记不自动打开链接。原生打开命令仅接受服务 ID，从 daemon 重新读取并验证地址，拒绝文件、自定义协议、控制字符、账号密码等输入。

## 独立托盘与稳定服务身份（beta.13）

服务卡片以收录的程序入口保持稳定身份，PID 只是某次运行的实例。重复启动已运行服务会复用当前实例；重新启动沿用卡片、页面地址、提醒与历史。旧重复记录可通过桌面合并归档，保留原始记录，不结束进程。

主动交接给 Windows 桌面的托盘可能脱离启动器进程组。可在管理中明确设置执行文件白名单（最多4个）与完整 argv 参数前缀（最多16项）；这仅提供有边界的独立进程观察，不证明来自该工作目录，也不提升工具信任或自动停止权限。后台只在读取该项状态/提交启动时查询进程快照，对白名单名字最多64个候选读取原生命令行；不读环境、凭据、磁盘文件树，不运行查询脚本。唯一候选才更新PID与创建时间；缺失/多个候选明确等待，不按名称猜测。停止需绑定界面显示的PID与创建时间，进程换代时必须刷新重新确认。当前独立观察只控制核验的单个进程，不猜测其外部树。

“进程运行”与“网页就绪”分开确认。仅启动包装进程不能证明网页可访问；系统代理链路与直连也可能不同。ToolHub 不自动修改代理例外，此次用户明确授权的本机例外属于单独故障修复，不是软件默认行为。
