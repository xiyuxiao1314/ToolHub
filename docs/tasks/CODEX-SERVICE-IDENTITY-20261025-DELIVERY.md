# 稳定服务身份修复交付 — 2026-10-25

分支 codex/service-identity，保留 e066942 之后所有已有本地开发成果。新版 beta.13 已构建、打包并本机激活，未提交/推送/发布 GitHub。

根因分为两部分：启动器与实际常驻进程不是同一身份，每次启动产生新PID被误建成新卡片；独立托盘会离开启动器进程组，手工登记某一次PID不能跟随后续换代。另一个连接问题是系统代理例外未包含该本地域名；之前的直连健康检查不足以证明默认浏览器可访问。

实现：同一程序复用稳定卡片与当前实例，重启保留网址/提醒/历史；已运行的关联服务重复提交启动返回当前实例。controller-only合并接口将旧启动记录归档，保留原始记录和合并备注，不终止任何进程。桌面可明确选择最多4个执行文件与16项完整argv前缀观察独立托盘；原生进程快照32768项上限、同名候选64项上限，只读取指定映像候选的当前用户信息和有界命令行，唯一匹配才更新PID。缺失/歧义显示等待，不猜测、不授予信任或自动停止。任何停止须绑定显示PID+创建时间，换代后的陈旧动作被拒绝；外部绑定仍只控制精确单进程，不伪造进程树归属。

验证：原生临时进程测试5项通过，3个子进程测试入口在顶层忽略、由通过测试实际调用；覆盖PID换代、歧义、陈旧停止、保留网址/记录ID、合并历史与连续启动不增卡片。MCP10、协议10通过；TypeScript/Vite、锁依赖release桌面/daemon/CLI构建通过。正式ToolHub接口完成该应用观察规则与旧记录归档，连续三次 program.launch 返回同一卡片同一实际托盘PID，关联程序仅1张可见卡片，地址保留。没有通过停止真实用户应用来测试，不修改其源码、私有交接环境标志或自启动配置。

用户明确另行授权仅添加本地域名的Windows当前用户代理例外。原始值及恢复所需信息在私有任务目录备份，原有例外保持原字串，仅追加1项；ProxyEnable/ProxyServer/PAC原值逐项核对不变，未停Clash/nano或编辑其软件配置。排除仅诊断子进程的代理环境变量干扰后，按WinINet代理配置读取 /healthz 严格TLS校验返回200。未修改全局环境变量或绕过证书。用户要求自行验证浏览器后，停止浏览器操作；后续只调用ToolHub自身配置/启动接口。浏览器页面实际验证由用户完成，不以API成功代替。
